# W6.5 interviews readiness

**State:** `READY FOR LOCKED IMPLEMENTATION`

## Existing persistence and contract fit

W4.1 already defines `FounderInterviewRecord` with schedule time, round, type, format, interviewer name, preparation notes, post-interview notes, outcome, and timestamps. `FounderActivityEventRecord` provides append-only events and a unique idempotency key. The application tracker states are already canonical in W6.2. A bounded interview service, routes, mock persistence, and Founder UI do not yet exist. No schema change is needed for the interview workflow.

## Testability

- Temporary in-memory SQLite can exercise eligibility, UTC normalization, validation, pagination, transactional event writes, idempotent retries/conflicts, no-op behavior, and rollback without a configured database.
- The MSW store can persist synthetic interview records and ID-only activity metadata across browser refreshes.
- Existing Chromium tracker and keyboard flows can cover interview CRUD, completion, privacy, and Tracker overview placement.
- The hosted adapter can return static 501 responses before hosted configuration or provider access.

## Deliberate boundary

Contacts are optional in FR-008 §9.10 and no normalized contact inventory exists; W6.5 stores the interviewer name on each interview and does not create a contact subsystem. The W4.1 tracker-document table stores document identities, but the application has no user-visible selectable document inventory. Avoid a fake document picker or reading private document/profile material: document/CV linking will be separately ordered after W6.5 with its identity-selection contract. Timeline/history UI and document associations remain later slices.

Proceed only against the existing W4.1 interview and activity-event tables. No migration, live database, private Founder content, corpus, provider, outbound action, deployment, or Founder review is part of this increment. Keep Founder-testable at 0% and report W6.5 as local-only reviewable code.
