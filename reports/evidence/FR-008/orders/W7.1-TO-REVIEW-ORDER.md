## Objective

Make the default Jobs / To Review feed consistently represent unprocessed work in both the SQLite-backed query and the browser mock. Save, Mark Applied, and Reject may remove a job from the feed only after the state write succeeds. An expired snooze returns to the inbox; an active or undated snooze stays out.

## Contract

- By default, exclude saved, applied/submitted, application-pipeline, rejected/closed, dismissed, and actively snoozed opportunities from To Review. Preserve explicit `include_tracked=true` behavior in the database query.
- Keep the existing SQL expiration semantics: a snooze with no expiry remains active; an expiry at or before the query's `as_of` is inactive and the opportunity resurfaces.
- Give the mock the same snooze-expiry behavior using its existing synthetic tracker state. A surfaced expired-snooze feed item must not be labelled as currently snoozed.
- Persist the mock tracker state before reporting a successful mutation. If browser storage rejects the write, restore the in-memory state and return a clear failure response so the UI leaves the card in To Review. Do not record a transition event for a failed state write.
- Keep the UI removal driven by a successful action response; do not add optimistic removal or Undo in this slice.
- Preserve action idempotency, tracker bucket placement, and existing API response shapes on success.
