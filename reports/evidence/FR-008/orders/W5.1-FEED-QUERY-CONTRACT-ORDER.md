## Objective

Extend the SQL-native feed query contract to cover the first persisted, useful filter/sort slice without corpus-wide Python filtering or schema changes. Surface the query contract through `GET /api/opportunities` using repeatable parameters for multi-select facets.

## First backed filter slice

- Preserve truth-pack scope, hidden/ineligible defaults, tracked/submitted exclusions, search, and existing scalar parameters.
- Add OR-within-facet, AND-across-facets filters for work mode, country, employment type, target tier, and normalized title family.
- Add independent capability-fit, preference, confidence, and priority score ranges.
- Add an upper posted-date bound alongside the existing lower-bound alias.
- Provide an explicit `unknown` selection for nullable country, tier, and title-family fields; treat stored `other` title family as unmapped. Persisted `unspecified` values remain selectable for non-null normalized fields.
- Add deterministic SQL sorts for Recommended, fit high/low, posted newest/oldest, and Remote First. Null score/date values sort last; every order ends in projection ID ascending. Remote First is only an ordering preference.

The query must apply filters before the count and page limit. It may query `feed_projection` and the existing tracking/action state tables through scalar subqueries, but must not hydrate the opportunity corpus or compute filtering in Python. The current page-only API serialization behavior remains bounded.

## Scope boundary

- No migration, backfill, scoring, filter/facet metadata generation, saved-view redesign, UI changes, tracker changes, live database, hosted database, or deployment.
- Filters without a persisted/economically queryable backing remain outside this W5.1 query contract; W5.2 will expose facet availability/count metadata and later waves add UI/sort breadth.
- Use synthetic temporary SQLite fixtures and offline PostgreSQL SQL compilation only.
