# W6.6 document/CV association readiness

**State:** `READY FOR ID-ONLY IMPLEMENTATION`
**Integration base:** `41fcd8f` (W6.5 integrated and pushed)

## Existing identity and persistence surfaces

- `FounderTrackerDocumentRecord` stores an opportunity-scoped document kind and opaque document ID, plus link/unlink timestamps. It is the existing association table; no schema change is required.
- `FounderApplicationDetailRecord` already has selected CV and cover-letter identity fields.
- `FounderCVSelectionRecord` stores the canonical CV variant identity selected for an opportunity.
- The fixed CV selector exposes an existing approved variant identity catalog in code. W6.6 will use only each variant's stable ID and curated safe label; it will not read or return private files, file names, object paths, checksums, or document bytes.
- Generated cover letters already have private `ArtifactCacheRecord` identities. Candidate listing can query only cache key, template, format, and created time for the same opportunity, excluding payload and storage metadata.

This provides a concrete ID-only picker without inventing document IDs or scanning Founder files. An arbitrary uploaded-document inventory is not present and remains out of scope.

## Safe testability

- Temporary SQLite can cover candidate projection from synthetic catalog/cache metadata, active link lifecycle, one-selected-per-kind behavior, application-detail synchronization, idempotency, conflicts, no-op behavior, and atomic event rollback.
- The MSW browser mock can use synthetic local-storage-only IDs for both candidate kinds. Tracker event metadata will contain only document kind and identity ID.
- The hosted adapter can return explicit static 501 responses before hosted configuration/auth/provider work.

## Boundaries

- Do not access `private/`, Founder profile/CV/truth-pack content, configured databases, hosted providers, artifact bodies, or corpus data.
- Never serialize CV filenames, object paths, SHA-256 values, artifact payloads, or note contents in candidates, linked-document responses, events, summaries, or logs.
- Support only stable CV variant IDs from the existing approved selector and cached generated-cover-letter IDs for the same opportunity. Reject arbitrary IDs.
- Reuse W4.1 tracker-document/application-detail/activity-event tables. No migration, schema edit, document generation, external action, or CV content delivery.
- Keep Founder-testable at 0%; no staging or terminal FR-008 acceptance.
