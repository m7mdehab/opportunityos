# W6.7 activity timeline readiness

**State:** `READY FOR READ-ONLY PROJECTION AND DETAIL UI`
**Integration base:** `aa8cef0` (W6.6 integrated and pushed)

## Existing substrate

- W4.1's `FounderActivityEventRecord` already has an opportunity-scoped index over event time, event ID, action type, from/to state, metadata, and idempotency key.
- W6.1/W6.2 tracker transitions and W6.3–W6.6 note, follow-up, interview, and document mutations already add append-only rows in the caller transaction.
- Known event metadata contains IDs only; event bodies and job content are stored elsewhere. The W6.7 list query can exclude metadata/idempotency columns entirely.
- Existing SQLAlchemy models support isolated temporary SQLite. The frontend mock already persists synthetic tracker events in the scenario-scoped tracker-events key.

## Safe local testability

- Temporary SQLite can seed only synthetic opportunity and event rows, prove bounded deterministic pagination and column selection, and check that reads do not write.
- Chromium can use the existing local mock namespace to cover state changes, child tracker mutations, safe labels, drawer refresh, reload persistence, and Tracker summary exclusion.
- The hosted catch-all route can return the explicit static 501 before hosted configuration/auth/provider code; the feature acceptance does not need an API server or external service.

## Scope boundaries

- Add a read-only endpoint and UI projection only. Do not alter event writers, records, migration/schema, current-state source, restore/undo, telemetry, feed data, or summary rows.
- The endpoint returns `id`, `action_type`, `from_state`, `to_state`, and `event_at` only. It must never select or serialize `metadata_json` or `idempotency_key`.
- No private Founder data, configured/live DB, corpus, provider, deployment, or Founder review.
