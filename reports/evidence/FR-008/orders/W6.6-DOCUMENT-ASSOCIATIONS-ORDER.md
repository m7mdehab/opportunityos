## Objective

Let the Founder associate one selected approved CV identity and, when a generated cover letter is already cached for the same job, one cover-letter artifact identity with an application. Reuse W4.1 tracker-document, application-detail, and activity-event records. This increment adds a small ID-only identity picker and association lifecycle; it does not read or deliver document content.

## Contract

- Add authenticated operations:
  - `GET /api/opportunities/{id}/tracker-documents` — bounded active associations for an application-tracked job.
  - `GET /api/opportunities/{id}/tracker-documents/candidates` — bounded ID/label candidates from the fixed approved CV variant catalog and this job's cached cover-letter artifact metadata.
  - `POST /api/opportunities/{id}/tracker-documents` — associate a candidate using `document_kind`, `document_id`, and required `idempotency_key`.
  - `PATCH /api/opportunities/{id}/tracker-documents/{link_id}` — unlink an association with `linked=false` and required `idempotency_key`.
- Allow `document_kind` values `cv` and `cover_letter`. CV IDs must match a variant ID from the canonical fixed selector portfolio. Cover-letter IDs must match an `ArtifactCacheRecord.cache_key` for the same opportunity and a cover-letter artifact kind. Reject all other IDs.
- Candidate and active-link responses expose IDs, safe display labels, kind, relevant template/format, and timestamps only. Never expose file names, paths, checksums, storage object keys, artifact bytes, CV content, or private notes.
- Candidate queries for generated cover letters must select only cache identity/template/format/time columns; do not hydrate `payload`, object metadata, or invoke generation/storage providers.
- Keep one active selected association per document kind. Replacing a selection closes the prior link row and activates or creates the chosen link row. Synchronize `FounderApplicationDetailRecord.selected_cv_document_id` or `selected_cover_letter_document_id` in the same transaction.
- Emit append-only `tracker_document_linked` / `tracker_document_unlinked` events for real changes only. Event metadata may contain only `document_kind` and `document_id`; use the current tracker state. No-op retries/edits add no event. Replays return the persisted association; conflicting reuse across identities/actions fails.
- Keep association/application-detail updates and events atomic in the caller-owned SQL transaction. No schema edit or migration.
- Eligibility is limited to application-tracked states (Applied and later/closed application states); Saved, To Review, and missing jobs are rejected.

## Founder UI and mock

- Add a document section to the detail drawer for application-tracked jobs with candidate loading, empty/error states, CV and cached cover-letter selection, current-link display, replace, and unlink controls.

- Add Chromium mock coverage for candidate privacy, CV association/replacement, cached cover-letter association, unlink/reload, no-op behavior, and event metadata.
