# W4.4 work order — bounded projection rebuild verification

- This work order is committed and pushed before source edits.

## Objective

Add a read-only, paginated invariant verifier for the W4.2 feed projection contract and prove the current projection rebuild path against synthetic temporary SQLite rows. The verifier reports aggregate issue counts and one-way tokens only; it does not repair rows or return source content.

## Invariants

- Stable projection identity matches opportunity ID plus requested truth-pack hash.
- The referenced opportunity exists; title, organization, and content hash match the current opportunity record.
- When an evaluation exists, truth-pack hash, decision, fit score, and evaluation timestamp match it. An evaluation-less projection carries no evaluation scores/decision/priority.
- Version `v2` family/level match deterministic title normalization. Preference/confidence are nullable finite numeric 0–100 values matching the current evaluation detail. Target tier is from the recognized domain and, when a graph is supplied, matches same-subject verified role/tier resolution.
- Legacy `v1` rows remain accepted with nullable W4.2 fields; do not interpret their NULLs as failures.
- Scan pages select only the scalar fields required for checks, use an exclusive ID cursor, and are capped at 100 rows with a one-row look-ahead. Never select job descriptions, raw payloads, CV/profile data, rationale text, or `search_text`.
- Output contains counts, a cursor, and hashed issue tokens only. Never print raw opportunity IDs or evidence.

## Scope boundary

Use only synthetic in-memory SQLite for tests. Do not run a rebuild or verifier on configured/application databases, connect to hosted storage, change evaluation/corpus rows, apply migrations, rerun scoring on real jobs, change ranking weights, or deploy. Real W4.3 reevaluation remains separately gated on the approved 150+ Founder-reviewed gold set and a safe local target.
