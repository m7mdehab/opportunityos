# W3.2 — Explicit preference score

## Deliverable

Implement the FR-008 preference score as a separate 0–100 score answering: “Assuming the job is feasible, how well does it fit the Founder’s stated preferences?” Read only verified positive TruthGraph preference assertions and directly comparable structured opportunity fields. Cover target-role family, work mode, employment type, geography, relocation, compensation, industry/company, time-zone, and travel where both sides provide comparable data. Missing or incomparable values remain unknown and are excluded from the preference average. If no preference can be compared, `preference_score` is null.

Keep preference fit out of objective capability fit and qualification. Compute employment capability fit from capability dimensions only; preserve hard qualification decisions as their own track. For procurement, use service capability, scope complexity, and portfolio evidence as objective fit dimensions. Preference-only and qualification-only uncertainty must not lower capability fit. Existing preference dimensions and premium-shortfall tagging remain readable for compatibility. Keep W3.1's uncalibrated capability placeholders uncalibrated; do not tune against the synthetic set or backfill any records.

Persist the preference score in the existing evaluation-detail JSON and expose it in the opportunity-detail API with a null fallback for historical rows. Do not add a schema migration in this slice.
