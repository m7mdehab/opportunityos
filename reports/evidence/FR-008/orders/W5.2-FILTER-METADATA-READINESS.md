# W5.2 readiness — feed filter metadata

## Inputs reviewed

- Integration base `9fac87b` contains W5.1's SQL feed query contract and exposes queryable projection-backed dimensions, four independent score bounds, posted-date bounds, and six deterministic sort keys.
- `feed_projection` contains the persisted scalar fields needed for the backed metadata. The projection also stores additional data, but this work will not read descriptions, URLs, search text, or serialized evaluation rationale.
- The legacy `GET /api/facets` is tied to a separate include/exclude settings feature. W5.2 will add a distinct metadata endpoint and leave that feature untouched.
- FR-008 §7 includes filter families without normalized query backing; those will be reported as unavailable with reasons until their relevant data contracts are implemented.

## Execution plan

1. Add a pure metadata service that produces SQL grouped counts and scalar aggregates for the active truth-pack/visible projection scope, plus a bounded and explicit capability catalog.
2. Add an authenticated additive route that resolves the active pack hash using the same feed fallback and passes it into the metadata service.
3. Add synthetic SQLite tests covering all aggregate semantics, count-only payload safety, statement-table scope, and route registration. Compile representative SQL offline for PostgreSQL.
4. Run focused and repository checks; preserve all raw outputs and push feature/integration checkpoints.

The query/metadata alignment may normalize whitespace on persisted categorical values. If that changes SQL text, refresh only the matching static SQL-string expectations in `storage/test_feed_regression.py`; retain its behavioral assertions and record the original stale-expectation failure.

- PostgreSQL validation: SQL compilation only; no connection.
