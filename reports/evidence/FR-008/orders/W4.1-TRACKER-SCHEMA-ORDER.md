## Objective

Add an additive, backwards-compatible persistence foundation for FR-008 tracker work. Current schema has only `founder_triage_states` (`state`, `snoozed_until`, timestamps) and no append-only Founder activity table or normalized tracker detail tables. Existing API still writes legacy `dismissed`/`snoozed`; this migration must not enforce the new state vocabulary or change current behavior.

Create migration `0015_fr008_tracker_foundation` and matching ORM models for:

- nullable `saved_at`, `applied_at`, and `closed_at` on the existing triage row; do not rewrite existing state values or infer dates;
- an append-only activity event table with action, from/to state, event time, structured metadata JSON, and nullable unique idempotency key;
- one-per-opportunity application metadata (method/reference and selected document identifiers);
- private notes, follow-ups/reminders, multiple interview records, and linked document/CV identifiers;
- immutable tracker snapshot metadata that captures the minimum scalar job/score/version fields and points to an existing `artifact_cache` cold object for content, without copying full descriptions into a hot table.

Do not add contacts in this migration; the brief makes them optional. Do not add check constraints over state/action vocabularies until the compatible transition API is implemented. New private tables must be denied to browser `anon` and `authenticated` roles under the existing Postgres RLS policy style. Add indexes for state/timestamps, event timeline/idempotency, follow-up due/completed, interviews by opportunity/date, document lookup, and snapshots by opportunity/content hash.

No data backfill, state conversion, source-content replay, API mutation, DB connection, migration application, or deployment is in scope. This order adds schema only. Query-plan evidence against PostgreSQL remains a later measured acceptance item.
