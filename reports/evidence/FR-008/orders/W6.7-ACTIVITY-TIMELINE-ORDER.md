## Objective

Show the append-only `FounderActivityEventRecord` history in an opportunity detail timeline. Reuse W4.1's indexed activity-event table and the event writers already delivered through W6.6. This slice is read-only: do not change event creation, current tracker state, schema, or event metadata.

## Contract

- Add an authenticated, bounded operation: `GET /api/opportunities/{id}/tracker-events` with `page` and `page_size`.
- Return the opportunity ID and a page of `{id, action_type, from_state, to_state, event_at}` items, newest first with deterministic timestamp/ID ordering. Cap page size at 100. A real opportunity with no activity returns an empty page; a missing opportunity returns 404.
- Query only the opportunity ID, event identity/type/states/time columns and a count. Never hydrate or serialize `metadata_json`, idempotency keys, note text, interview/follow-up details, CV file information, or any opportunity/corpus content beyond the existence check.
- Do not change or infer events. The timeline displays stored event type and state transitions with safe generic labels; unknown future event types receive a generic label. Do not render activity metadata or event IDs as user-facing text.
- Add the activity timeline to the detail drawer for any opportunity. Show loading, empty, error, and bounded results. Refresh it after successful tracker actions and notes, follow-up, interview, and document mutations in the open detail drawer. Keep activity out of feed and Tracker summary rows.
- The MSW mock reads the existing synthetic append-only tracker event list from its local mock store and returns the same privacy-safe projection. No new mock storage namespace is needed.
