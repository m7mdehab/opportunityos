## Objective

Deliver an interview-tracking vertical slice from FR-008 §9.11 and §10.3. A Founder can keep multiple interview records on an Applied-bucket job, record schedule/round/type/format/interviewer, keep private preparation and post-interview notes, update an outcome, and see upcoming interviews in Tracker.

Reuse W4.1 `FounderInterviewRecord` and `FounderActivityEventRecord`. Persist each real interview mutation and its append-only activity event in one caller-owned transaction. Do not add or apply a migration.

## Contract

- Add authenticated API operations:
  - `GET /api/opportunities/{id}/interviews?page=1&page_size=50` — bounded pagination for all interview records on the opportunity.
  - `POST /api/opportunities/{id}/interviews` — create an interview with optional `scheduled_at`, `round_label`, `interview_type`, `interview_format`, `interviewer_name`, `preparation_notes`, `post_interview_notes`, and `outcome`, plus a required `idempotency_key`.
  - `PATCH /api/opportunities/{id}/interviews/{interview_id}` — update supplied fields, including explicit null to clear optional values; require `idempotency_key`.
  - `GET /api/tracker/interviews?bucket=upcoming&page=1&page_size=25` — bounded upcoming-interview summary across eligible application states, omitting notes.
- Cap page sizes at 100. Require any supplied schedule datetime to carry an explicit UTC offset; normalize to UTC and return ISO 8601 with `Z`. Unscheduled interviews remain valid.
- Allow records for canonical Applied-bucket states (`applied`, `recruiter_screen`, `assessment`, `interviewing`, `final_interview`, `offer`, `accepted`). Reject Saved, To Review, rejected, withdrawn, no-response, and other terminal jobs.
- Support the FR-008 interview types `recruiter_screen`, `hiring_manager`, `technical`, `take_home`, `live_coding`, `case_study`, `panel`, `final`, and `other`; formats are `phone`, `video`, and `in_person`. Trim optional text and enforce reasonable field-length limits; private notes are returned only by the per-opportunity endpoint.
- Use outcomes `pending`, `completed`, `passed`, `not_selected`, `cancelled`, and `other`. A transition from pending/empty to `completed`, `passed`, or `not_selected` records `interview_completed`; create records `interview_added`; other real edits record `interview_updated`. Each event uses the current tracker state and metadata containing only `{ "interview_id": "…" }`. No-op edits and repeated outcomes add no event.
- Idempotent replay returns the persisted interview without another event; reusing a key for another interview or action conflicts. Keep interview mutation and event atomic.

## Founder UI and mock

- Add interview management in the detail drawer for Applied-bucket opportunities, with create/edit, completion/outcome, loading/empty/error states, and safe display of schedule times.
- Add an Upcoming interviews section to Tracker with links to the corresponding tracked job. Do not show preparation or post-interview notes in summary rows.
- Persist only synthetic records and idempotency in a dedicated local-storage namespace. Keep activity metadata ID-only and notes out of tracker summaries, feed projections, ranking, prompts, and telemetry.
- Add Chromium mock coverage for eligibility, upcoming placement, create/edit/complete/reload, no-op event behavior, and private-note exclusion from summaries.
