# W2.3 — Mandatory, preference, and contextual requirement extraction

## Deliverable

Add a typed priority classification for extracted requirements: mandatory, strongly preferred, nice to have, contextual, and unknown. Classify structured requirement bullets using their source section and explicit wording; classify skills mentioned in full descriptions using the existing headed-list structure plus direct requirement cues. A general technology mention in company/about-role prose is contextual, not a candidate requirement. Unheaded or unsupported skill mentions remain unknown. When the structured skill list is empty, use the full job description for extraction before reporting a neutral skill dimension. Preferred and contextual skills must never be promoted to mandatory strengths.

Keep legacy helper behavior available for its existing callers. Do not change qualification decisions, requirement evidence wording, scoring weights, or requirement support evidence in this slice.
