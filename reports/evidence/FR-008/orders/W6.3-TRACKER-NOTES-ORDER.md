## Objective

Deliver the first W6.3 Checkpoint H vertical slice: private notes attached to an actively tracked application. A Founder can list, add, edit, and archive notes from the existing opportunity detail drawer. Keep note content out of model/scoring inputs and activity-event metadata.

Reuse `founder_tracker_notes` and `founder_activity_events` from the already integrated W4.1 schema. Do not add or apply a migration. Persist each real note mutation and its corresponding append-only activity event in one caller-owned transaction.

## Contract

- Add authenticated API operations:
  - `GET /api/opportunities/{id}/tracker-notes?page=1&page_size=50` — paginated active notes for an eligible tracked application; `page_size` is capped at 100.
  - `POST /api/opportunities/{id}/tracker-notes` — create a note from nonblank `note_text` and a required `idempotency_key`.
  - `PATCH /api/opportunities/{id}/tracker-notes/{note_id}` — edit `note_text`, or archive with `archived: true`; require an `idempotency_key`.
- Limit note text to 4,000 characters after trimming. Reject blank text and invalid payload combinations.
- Restrict notes to application-tracked rows: `applied`, active pipeline stages, `accepted`, and the application terminal outcomes. Do not expose notes for untracked/to-review jobs.
- Every real create, edit, or archive inserts exactly one activity event in the same transaction. Use action types `tracker_note_created`, `tracker_note_updated`, and `tracker_note_archived`; set both event state fields to the current tracker state. Put only `{ "note_id": "…" }` in event metadata. Never include note text.
- Replaying the same idempotency key for the same operation returns the original result without another mutation/event. A key reused for a different operation or note is rejected. Editing to the current text and archiving an already archived note are no-ops.
- Archived notes are excluded from ordinary list results. Notes cannot be restored in this increment.
- Return note content only to the authenticated caller; never feed notes to matching, ranking, qualification, prompts, or telemetry.

## Founder UI and mock

- Show the Notes panel in the existing detail drawer only for application-tracked rows.
- Support create, edit, and archive; display archived notes only as absent from the active list. Provide clear loading, empty, and error states.
- Preserve only synthetic mock notes in a dedicated local-storage namespace across refresh. Emit synthetic mock events with metadata that contains a note ID only.
- Add Chromium mock coverage for create/edit/archive, refresh persistence, and no extra event on idempotent/no-op operations.

## Hosted boundary

The hosted adapter must explicitly return 501 for tracker-note GET/POST/PATCH until an atomic hosted operation can enforce authorization, private-note persistence, and append-only event creation together. Do not call a provider, use generic PostgREST access, or emulate the transaction with separate writes. Preserve the existing 501 boundary for tracker actions.
