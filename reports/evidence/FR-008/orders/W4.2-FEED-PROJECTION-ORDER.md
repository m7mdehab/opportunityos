## Objective

Populate the minimal feed-projection fields needed by the FR-008 title/tier filters and score breakdown, using the existing deterministic title normalizer and persisted match evaluation. Add the fields additively so current readers and legacy projection rows remain compatible.

## Population contract

- Derive `title_family` and `title_level` from `matching.title_family.normalize_title(opportunity.title)` whenever a projection row is built. Store the normalizer's `other`/`unspecified` values as-is; do not infer a family from description text or the current corpus.
- Derive `target_tier` only from the supplied TruthGraph. A posting family maps to `primary`, `adjacent`, or `stretch` only when at least one verified, positive `career.target_role` assertion matches that normalized family and every such matched role has the same explicit verified, positive `career.target_role_tier` assertion on that same subject. Conflicting tiers or a matched role with no explicit tier produce `NULL`.
- Store `outside_targets` only when there is at least one verified, positive Founder target-role assertion, the posting has a recognized family other than `other`, and no verified target-role assertion normalizes to that family. No verified target roles, an `other` posting family, and unknown/ambiguous matches remain `NULL`; they must not be mislabeled outside-target.
- Persist `preference_score` and `confidence_score` from the current evaluation detail as independent nullable 0–100 values. Missing, malformed, non-finite, boolean, or out-of-range values remain `NULL`; never invent or clamp a score. Use these sanitized values for the existing Recommended priority calculation without changing its component order or weights. Keep `fit_score` and `priority_score` separate.
- Set the projection version to `v2` for rows built with this contract.
- Add only nullable projection columns and supporting indexes in migration `0016_fr008_projection_fields`. Do not rewrite existing projection rows or evaluation payloads.
