## Objective

Implement the brief's default Recommended feed ordering using the existing `feed_projection.priority_score` field. Keep all components separately visible in list API rows: eligibility decision, capability fit, preference score, confidence score, posting freshness, source confidence, and the resulting composite. No new migration or corpus backfill is in scope.

The comparator policy is: Founder-configured `rank_only` filters remain an explicit demotion tier; then eligible/qualified jobs before review-required/uncertain jobs; capability fit; preference; confidence; posting freshness; source confidence; deterministic opportunity-ID tie-break. Ineligible rows are excluded by default, while an explicit `decision=ineligible` filter can include them. Tracked/submitted jobs are excluded from the default To Review feed; `include_tracked=true` is the explicit override. An expired snooze resurfaces.

The existing numeric priority column will encode this lexicographic order with deterministic integer component buckets (0–100), keeping the stored value within exact integer precision for the existing Float column. API rows will expose unquantized component values separately. Missing preference/confidence/freshness/source values use a neutral midpoint for ordering and remain null/unknown in the visible component payload; they are not treated as negative evidence.
