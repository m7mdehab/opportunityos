# W4.1 R1 remediation order — raw offline SQL evidence vs diff guard

## Trigger

The first staged `git diff --cached --check` is red because Alembic's raw PostgreSQL SQL renderer emits trailing spaces after column declarations and blank final lines. The exact diagnostics appeared in the staged-check output. The unmodified raw upgrade and downgrade outputs are preserved at `W4.1-R1-migration-sql.txt` and `W4.1-R1-down-migration-sql.txt` and must remain byte-for-byte intact as evidence.

## Finding

The whitespace is generated by Alembic's renderer in otherwise successful offline SQL output; it is not a source-code whitespace defect. Committing the renderer output as plain text makes the repository-wide diff guard fail.

## Authorized remediation

1. Capture the complete R1 diff-check output under `W4.1-R1-diff.txt` without editing it.
2. Store each raw SQL output byte-for-byte as an entry in a ZIP evidence archive; record SHA-256 digests for the original files and archive entries.
3. Update the work-order evidence format to allow the binary archives and document that the raw `.txt` entry inside each archive is the unchanged R1 output.
4. Exclude the generated-whitespace logs from the text diff, rerun the full repository/diff closure, and preserve those results under a new R4 run.

Do not rewrite the raw SQL contents, adjust migrations to silence the renderer, or treat the initial red diff guard as green.
