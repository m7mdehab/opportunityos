## Objective

Make the existing Founder feed, filters/sorts, opportunity detail, triage, and tracker workflows usable by keyboard and at a 390px mobile viewport. Close the brief's Wave 7.4 accessibility gap and add the mobile repeat of the critical path called for by acceptance A-27.

## Contract

- Preserve keyboard navigation and visible focus across feed cards, filters/sort controls, detail drawers, tracker navigation, and tracker actions. Escape closes overlays where expected and focus returns to a sensible trigger.
- At 390px, the filter drawer, applied-filter chips, sort controls, card-level triage, detail explanations, tracker stages, follow-ups, Undo, and activity history remain reachable and readable.
- A user must not need horizontal scrolling or drag-and-drop to complete the mobile critical path. Prevent unintended page-level horizontal overflow.
- Run accessibility checks on the feed and the main open overlay states. Fix actionable violations introduced by or exposed in these surfaces.
- Add desktop and 390px browser coverage for the critical A-27 flow: filter and sort, save/query view, Save/Applied/Rejected placement, stage change, follow-up, Undo/restore, and detail history across refresh. Use synthetic mock data only.
- Keep the existing keyboard shortcut guard: shortcuts must not fire while a text input, button, link, or overlay owns interaction.
- Keep hosted and mock behavior clearly distinct. Mock-only success is not hosted persistence proof.

## Boundaries
