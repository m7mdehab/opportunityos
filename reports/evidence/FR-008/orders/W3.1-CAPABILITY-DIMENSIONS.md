# W3.1 — Distinct capability-fit dimensions

## Deliverable

Make the employment fit breakdown expose separate, evidence-backed capability dimensions for role/title-family history, skills, experience/responsibilities, seniority/years, domain relevance, and education/certification alignment. Add credential evidence only from verified positive Founder assertions. Parse credential requirements only when the posting establishes an applicant-facing requirement or preference; unstated or ambiguous credentials remain unknown/neutral. Preserve unknown when the Truth Graph has no relevant record and never infer that the Founder lacks a skill, degree, or certification from missing data. Split the existing combined seniority/experience signal into distinct dimensions. Do not tune or lock weights from the three-item synthetic set; retain compatibility and keep the real-gold calibration/backfill gate closed.

Role-family fit in this slice must use verified employment role history for capability evidence. Any existing target-role preference signal is not evidence of capability and remains separately visible for later preference-score work. Work mode and compensation remain separate non-capability dimensions. Existing score persistence and API dimension serialization must continue to handle new dimension names without schema changes.
