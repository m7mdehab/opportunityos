# W6.3 tracker notes readiness

**State:** `READY FOR LOCKED IMPLEMENTATION`

## Existing persistence and privacy boundary

W4.1 already defines `founder_tracker_notes` with an ID, opportunity ID, note text, created/updated timestamps, and archive timestamp, plus an opportunity/created-time index. It also defines `founder_activity_events`, whose migration installs an append-only trigger on PostgreSQL. Private tracker tables enable RLS and revoke browser-facing grants. Existing SQLAlchemy models are available for notes, triage state, and activity events. No new schema or migration is needed for this slice.

No current API CRUD path was found for tracker notes. The current server-side tracker pattern writes the canonical triage row and append-only event through a caller-owned SQLAlchemy transaction. W6.3 can follow that pattern while keeping the note row and its event in one transaction.

## Testability

- Temporary in-memory SQLite can exercise service behavior, transactional rollback, event counts, idempotency, and bounded listing without contacting an application database.
- Existing MSW mock handlers, mock store/local-storage persistence, and Chromium Playwright tracker coverage support an isolated browser flow with synthetic notes only.
- TypeScript, ESLint, Playwright, `python scripts/check_repository.py`, and `git diff --check` are available.
- The hosted adapter returns 501 for tracker mutations and otherwise falls through for unsupported routes. W6.3 must add an explicit note-route 501 before that fallback and must not use a provider.

## Decision and boundaries

Proceed with the pushed W6.3 order in a feature worktree based on its docs-only integration checkpoint. Keep notes limited to application-tracked rows and their detail drawer. Metadata contains note IDs only. No private profile/CV data, external service, migration, live database, deployment, or Founder review is part of this increment.

No safe hosted write/test surface or staging target is configured. Keep Founder-testable at 0%; report the implementation as partial and locally reviewable only. Follow the incremental delivery manual by pushing the coherent code checkpoint and continuing into W6.4 without treating Founder review as a blocking gate.
