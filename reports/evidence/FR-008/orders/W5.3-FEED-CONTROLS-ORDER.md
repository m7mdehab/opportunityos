## Objective

Connect the W5.1 feed-query contract and W5.2 metadata endpoint to Founder feed controls. Keep every filter family visible: expose backed fields as real query controls and show unsupported fields/sorts disabled with plain reasons. Preserve the separate semantics of policy filters (`hide`/`rank_only`/`label_only`) and legacy include/exclude facets.

## Backed query controls

- Keep full-text search, track, decision, and the existing fit-score shortcut visible.
- Add one Sort dropdown for the six W5.1 server-supported sorts: Recommended, fit high/low, posted newest/oldest, and Remote First. Keep the remaining FR-008 §8 sorts visible under an unavailable group with a reason; never send an unsupported sort.
- In a discoverable advanced panel, expose multi-select work mode, country, city, remote scope, employment type, seniority, target tier, title family, and source ID. Track and decision remain single-select, matching the query contract. Provide search for long value lists.
- Expose independent min/max controls for fit, preference, confidence, and priority; quick minimum thresholds 90+, 80+, 70+, 60+, and 50+; and posted-date bounds.
- Preserve OR within one multi-select facet and AND across facets by serializing repeatable query parameters. Use W5.2 counts with their stated truth-pack/visible/selection-independent scope.
- Show removable active-filter chips and Clear all. Persist the full filter/sort/page state in the URL and restore it on refresh/back navigation.
- Use the existing saved-view API/table to save and apply the complete feed query object. Preserve legacy facet-only views and prevent feed-query views from being applied as C1 facet selections. No migration.
- Show every W5.2 unavailable filter family, disabled with its reason. Search/unknown semantics remain explicit.

## Adapter and mock behavior

- Extend the mock API with synthetic metadata and query behavior so the Founder-facing controls can be reviewed without live data.
- The hosted Cloudflare adapter currently lacks an aggregate/query endpoint for this contract. Respond explicitly that advanced feed-query metadata is unsupported there, and disable advanced controls with a visible reason rather than silently accepting no-op filters. Preserve existing hosted search/track/decision/fit-min controls.
- Do not connect to or mutate Supabase, hosted APIs, or any application database.
