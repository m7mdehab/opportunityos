# W4.3 work order — bounded reevaluation batch selection

## Source lock

- Integration branch: `work/fr008-incremental-delivery`
- Integration base: `63ff668`
- Feature branch: `work/fr008-w43-bounded-reevaluation`
- This work order is committed and pushed before source edits.

## Objective

Add a read-only, keyset-paginated batch selector as the bounded foundation for a future FR-008 reevaluation worker. It returns only opportunity IDs, caps one batch at 100 records, and reports whether another page exists. It does not perform scoring, change canonical records, enqueue queue jobs, or rebuild projections.

## Contract

- Select `OpportunityRecord.id` in ascending order using `id > start_after`; do not use `OFFSET` and do not hydrate descriptions or raw payloads.
- Accept a batch size from 1 through 100 (default 100); reject booleans, non-integers, zero, negative values, and values above the hard cap.
- Return at most that many IDs, a resumable last-ID cursor, and a `has_more` flag based on one bounded look-ahead row.
- Repeating the same cursor returns the same selection while the underlying ID set is unchanged. After an interrupted consumer, repeating the same cursor is safe; evaluation persistence already upserts by `(opportunity_id, truth_pack_hash)`.
- The future execution path must use FR-007's durable queue, leases, bounded worker runs, per-row idempotent persistence, and explicit cursor continuation. It must not repoll or reingest source material.

## Scope boundary

This checkpoint implements batch selection only. Do not evaluate or update any opportunity or match-evaluation row, enqueue a worker job, rebuild a projection, connect to an application DB, apply a migration, backfill a corpus, or deploy. Before real-corpus reevaluation or score calibration, the separate gate requires at least 150 real Founder-reviewed jobs with passing W3.5 metrics and an approved safe local database target. Neither gate is satisfied in this task state. No production score or weight changes are allowed.
