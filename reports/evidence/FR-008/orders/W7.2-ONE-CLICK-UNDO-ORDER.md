## Objective

Let the Founder Save, Mark Applied, or Reject an employment opportunity directly from its To Review card. After a successful change, offer a short Undo action that durably restores the exact prior triage state and appends a reversal event.

## Contract

- Add card-level Save, Mark Applied, and Reject controls without nesting interactive controls or changing the detail-open action. Keep Mark Applied an explicit founder attestation; opening a posting remains read-only.
- The existing detail-drawer triage actions also provide Undo after a successful Save, Mark Applied, or Reject. A failed write shows an error and creates no Undo offer.
- Include an internal undo-event identity in successful state-action responses. Do not render this ID or idempotency keys as user-facing text.
- Add an authenticated `POST /api/opportunities/{id}/restore` operation taking the original event ID and an idempotency key. It may reverse only the latest activity event when that event is a Save/Mark Applied/Reject transition and the current state still matches its `to_state`; stale or unrelated events return 409 without writing.
- Restore the original `from_state`, including an existing snooze expiry when applicable. Append one `restore` activity event in the same transaction. Idempotent retries of the same Undo return the prior reversal without another event.
- Undoing Mark Applied retains the Founder-attested outbound-action row for audit but marks it `undone`, so it no longer suppresses an opportunity whose restored state is To Review. No external submission is performed.
- Give the mock API the same one-click, Undo, stale-request, retry, feed, tracker, and activity-history behavior. A storage failure must keep the prior state and leave the card in the queue.
- Keep the Undo prompt short-lived and usable after the card disappears. Clear it after Undo, expiry, or a newer triage action.

## Boundaries

- This is Undo for the immediately preceding successful Save/Mark Applied/Reject action. Do not add bulk actions, arbitrary Rejected/Closed restore, or general history editing.
- No schema migration; reuse the existing tracker and append-only activity event table. No configured/live database, provider, corpus/backfill, private Founder data, deployment, PR, merge, or `docs/STATE.md` change.
- Keep Founder-testable at 0%; report local-only and partial, not FR-008 terminal PASS. Preserve user-supplied untracked briefs and W0 evidence without staging or editing them.
