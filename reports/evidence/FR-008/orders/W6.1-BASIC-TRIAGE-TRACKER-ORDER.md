## Objective

Deliver the FR-008 Follow-Up Checkpoint F workflow using the existing tracker foundation: Save for later, explicit Mark Applied, and Reject. Successful mutations must persist canonical triage state and an append-only activity event, leave To Review only after the durable mutation succeeds, and appear in the appropriate Tracker bucket. Preserve existing `dismiss`/`snooze` behavior for compatibility.

## State and API contract

- Use `founder_triage_states` as the sole current triage state; do not add another saved/applied/rejected state store or schema migration.
- Add canonical states `saved`, `applied`, and `rejected_by_founder` for new tracker actions. Keep `dismissed`, `snoozed`, and submitted outbound-action compatibility intact.
- Save, Mark Applied, and Reject are authenticated operations. Mark Applied is only an explicit Founder action; opening a source URL never changes state.
- A real state transition writes exactly one append-only `founder_activity_events` record with action type, previous state, next state, and event time. Repeating the same action is an idempotent no-op and must not duplicate the transition event or founder-attested outbound action.
- Preserve the existing founder-attested outbound-action record on explicit Mark Applied. Do not reserve an automated-submission idempotency key or imply that OpportunityOS submitted the application.
- Add a bounded, paginated tracker-list operation for `saved`, `applied`, `rejected`, and `all`. The Applied bucket contains the applied state in this slice; Rejected contains Founder rejection plus legacy dismissed rows. All excludes `to_review` and snoozed-only rows.
- Continue to use the standard opportunity card/detail representation, expose the canonical tracker state, and leave non-tracked feed filtering semantics intact.

## Founder UI and mock

- Add a clear Jobs / Tracker mode switch and Saved / Applied / Rejected / All Tracked buckets with counts or empty states.
- Keep Save, Mark Applied, and Reject discoverable from the existing detail drawer. Only update the visible list after the server confirms success; refresh the relevant list after a mutation.
- Provide deterministic synthetic mock state for transitions and tracker buckets. Do not use real job or Founder data.
- Add one mock browser flow covering Save, Mark Applied, Reject, correct bucket placement, To Review removal after success, refresh persistence within the mock session, and proof that opening the source link alone does not mark Applied.
