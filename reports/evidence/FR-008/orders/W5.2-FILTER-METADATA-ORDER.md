## Objective

Add a read-only, additive feed metadata endpoint that reports available values and counts for the W5.1 queryable dimensions, score/date ranges, and supported sorts. Explicitly report filter families from FR-008 §7 that lack a queryable backing so a later UI does not present them as active filters.

## Backed metadata

- Scope all counts to the selected active truth-pack hash and visible `feed_projection` rows. Counts are independent of other selected filters and include rows excluded by the default tracked/submitted or ineligible feed view; document that scope in the response.
- Group categorical counts in SQL for track, qualification decision, work mode, country, city, remote scope, employment type, seniority, target tier, title family, and source ID. Normalize case/whitespace in the same way as the W5.1 query filters; report null/blank as `unknown`, and title family `other` as `unknown`.
- Bound returned facet options, report total distinct option count and whether values were truncated, and return counts only (no opportunity IDs, titles, URLs, or descriptions).
- Compute min/max, unknown counts, and 90+/80+/70+/60+/50+ counts for fit, preference, confidence, and priority scores in SQL. Report posted-date min/max and unknown count from the projection.
- Return the sort keys already supported by W5.1.
- Provide stable IDs and concise reasons for unsupported or partial FR-008 §7 filter families. The catalog is static capability metadata; it must not imply those filters are active.

## Constraints

- Do not change the legacy `GET /api/facets` settings endpoint or its behavior.
- Query only scalar/count aggregates from `feed_projection`; no corpus hydration, private profile reads, or user-specific/private data.
- No UI wiring in W5.2, schema changes, migration, corpus backfill/evaluation, deployment, or live/staging database access.
- Use synthetic temporary SQLite fixtures and offline PostgreSQL SQL compilation only.
