# W3.4 — Recommended ordering report

**Feature status:** GREEN / REVIEWABLE / NOT FOUNDER-TESTABLE

## Implemented

- The existing `feed_projection.priority_score` now stores a deterministic base-101 lexicographic composite: eligibility tier, capability fit, preference, confidence, posting freshness, then source confidence. Each component is quantized to a 0–100 integer bucket for ranking; source values remain individually visible in the list payload.
- Missing preference, confidence, freshness, and source-confidence values use the neutral ordering bucket (50) and stay null in the API breakdown. Capability fit remains unchanged in storage.
- Existing `rank_only` filter penalties remain an outer demotion tier. ID ascending is the final tie-break after priority.
- The default feed omits proven ineligible rows, active Founder triage states/snoozes, and submitted jobs. `decision=ineligible` and `include_tracked=true` are explicit overrides; expired snoozes resurface.
- List API items now include a `ranking` object with priority, eligibility tier, capability fit, preference, confidence, posting freshness, and source confidence. No migration or backfill was added.
