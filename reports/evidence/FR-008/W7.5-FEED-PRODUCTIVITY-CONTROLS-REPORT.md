## Delivered

- Each feed card has a tappable checkbox. The Jobs feed has Select all visible, Clear selection, selected count, and a compact responsive batch toolbar for Save, Reject, and Mark Applied. Batch work runs through the same per-item submit/transition handler used by card actions; Mark Applied asks for one confirmation. The batch processes each selected ID independently, keeps successful transitions, reports failed IDs, and leaves failures selected.
- Fit Score — Highest first and Fit Score — Lowest first use the existing SQL feed sorts over the canonical persisted `fit_score`, with the existing projection-ID tie-break and null ordering.
- Dashboard KPIs switch among Today, Yesterday, Specific date, and All time. The same event-window definitions are used for each period. All-time uses aggregate counts; Hidden is the matching discovered-job cohort evaluated against current hide filters. The dashboard’s day boundaries remain UTC, matching the prior endpoint.
- Track and Decision now accept multiple values in the primary checklist controls. The advanced query drawer provides multi-select checklists for Feedback, Activity, Source, Work Mode, Country, City, Remote Scope, Employment Type, Seniority, Target Tier, and Title Family. Existing repeated query parameters supply OR within a facet; separate query fields are ANDed. Feedback and Activity query existing tracker/feedback tables with correlated `EXISTS`, and their option counts come from grouped event metadata.
- URL query state preserves repeated feed selections. A hard refresh resets batch selection. Switching KPI periods refreshes metrics immediately; the metric period itself is not persisted in the URL.
