# W5.1 SQL feed query report

**State:** Built and integrated for review. This query/API checkpoint does not complete Wave 5 or FR-008 acceptance.

## Delivered

Extended `FeedQuerySpec`, `build_feed_query`, and `ordered_feed_query` to keep the first useful backed filter/sort slice in SQL. Repeated values use OR within each facet; different facets are combined with AND before total count and pagination. Supported fields include work mode, country, city, remote scope, employment type, seniority, target tier, title family, and source ID. Fit, preference, confidence, and priority ranges are independent; posted-date bounds preserve the existing `since` alias.

The API exposes those filter values as repeatable query parameters. Sort choices are Recommended, fit high/low, posted newest/oldest, and Remote First. Each sort ends with projection ID ascending; nullable score/date values sort last. Remote First changes only order and does not change eligibility, fit, or priority. `unknown` selects nullable country/city/tier and unknown or `other` title families; normalized non-null enum fields use their stored `unspecified` value.

The query still scopes to the current truth-pack hash, preserves hidden/ineligible/tracked/submitted behavior and PostgreSQL full-text search, and reads from persisted projections plus existing state/action predicates. It does not hydrate the corpus or apply filters in Python. Unbacked filter families, saved-view persistence, facet metadata, UI controls, and the broader sort catalog remain for later W5 slices.
