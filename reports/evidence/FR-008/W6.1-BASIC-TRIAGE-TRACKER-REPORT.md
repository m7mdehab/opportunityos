# W6.1 basic triage tracker report

## Outcome

W6.1 implements the basic tracker workflow using the existing `founder_triage_states` and `founder_activity_events` persistence. The feature checkpoint `f9cf88e` was cherry-picked onto the integration branch as `93a27b9`. Save, explicit Mark Applied, and Reject transitions use canonical tracker states, write an append-only transition event on change, and treat a repeated request as a no-op. Mark Applied preserves the founder-attested outbound record and does not reserve automated-submission idempotency. Existing dismiss and snooze behavior remains available.

The API provides bounded, SQL-filtered pages for Saved, Applied, Rejected, and All Tracked. The feed retains its existing review filtering; a tracked item leaves To Review only after the mutation succeeds. The UI adds a Jobs / Tracker switch, bucket tabs, action feedback, and keyboard action coverage. Opening an external posting never marks it applied. Synthetic browser state persists across refresh for the mock session.

The Cloudflare adapter returns an explicit 501 for tracker list and action requests until a single atomic state-plus-event write surface is available. The detail drawer reports the failure and keeps its displayed state unchanged.
