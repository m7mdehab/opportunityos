## Delivered

- Added authenticated, bounded API operations to list active application document associations, list candidates, link a candidate, and unlink an association. Supported document kinds are `cv` and `cover_letter`.
- Reused the existing W4.1 tracker-document, application-detail, and activity-event records. No migration or schema change was made. Link replacement, selected-ID synchronization, and the ID-only activity event share the caller-owned transaction.
- CV candidates are projected from the approved selector identity catalog with safe labels. Cover-letter candidates are queried for the same opportunity using only identity and safe metadata columns. Candidate/link/event responses do not contain file names, object paths, checksums, bytes, payloads, or private notes.
- Added a detail-drawer picker for tracked applications with loading/error/empty states, CV and cached cover-letter choices, replacement, and unlink. It contains no preview or download flow and does not add document details to Tracker summary rows.
- Added a dedicated scenario-scoped synthetic mock namespace with synthetic candidates, associations, and idempotency records. Its activity metadata carries only `document_kind` and `document_id`.
- The hosted adapter maps all four document route shapes to static 501 responses before hosted configuration, CSRF, or auth/provider calls. No hosted provider was contacted.
