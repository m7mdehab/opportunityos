# W6.2 application pipeline report

## Outcome

The feature branch adds explicit application-stage transitions on top of W6.1. `founder_triage_states` remains the only current-state row; each real stage change adds one append-only `application_stage_updated` event with its previous and next state. Repeating the current stage creates no event. The Founder can move forward through recruiter screen, assessment, interviewing, final interview, offer, and accepted, including skipping ahead. Rejected by employer, withdrawn, and no response are terminal outcomes. Backward and post-terminal transitions are rejected.

The Applied tracker bucket includes active stages and Accepted. The Rejected bucket includes the three employer/Founder terminal outcomes already represented by the tracker contract. The detail drawer shows the stage selector only while a pipeline is active, and closed states have no stage action. The mock API records synthetic events and state in separate local-storage entries so refresh and no-duplicate-event behavior are testable.

Stage transitions do not write outbound application actions. W6.1 Mark Applied continues to produce the single Founder-attested action. The hosted adapter retains its 501 response until an atomic state-plus-event operation exists.
