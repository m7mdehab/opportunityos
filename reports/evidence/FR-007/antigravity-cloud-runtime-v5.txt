1. EXACT FAILING / HANGING W7 STEP ROOT CAUSE
--------------------------------------------------------------------------------
In the W7 smoke suite (GitHub run 35224983310):
- Step `smoke_api_configurable_port` executed:
    `docker run --rm ... api --help`
- `scripts/container_entrypoint.py` ignored `extra_args` for the `api` role and
  unconditionally launched `uvicorn api.app:app` as a foreground process.
- Because `subprocess.run` had no timeout and CI had no per-command watchdog,
  Uvicorn listened on port 9090 indefinitely waiting for HTTP requests.
- Similarly, `scheduler --help` ignored `--help` and would launch an infinite
  scheduler loop.
- The workflow ran until GitHub Actions hit its 15-minute job timeout and cancelled
  run 35224983310.

2. EXACT REPAIR IMPLEMENTATION
--------------------------------------------------------------------------------
A. Bounded Process Execution & Watchdogs:
   - Added bounded per-command timeout to `_exec` in `scripts/smoke_container.py`
     (default 30s, 300s for image build, 60s for migrations).
   - On `subprocess.TimeoutExpired`, logs clear error diagnostic, terminates the
     process tree, forcibly kills and cleans up any running container (`docker rm -f`),
     and fails the step immediately.
   - Set `PYTHONUNBUFFERED: "1"` in the workflow and unbuffered output in Python.
   - Reduced workflow timeout to 10 minutes.

B. Decoupled Role Verification Contracts:
   - Added `--dry-run` to `scripts/container_entrypoint.py` for pure command construction
     contracts without launching background servers or daemons.
   - Replaced fragile `--help` calls with deterministic `--dry-run` verification for
     api, worker, scheduler, and migrate roles.
   - Handled `--help` gracefully (exits 0 with usage text).

C. Eliminated Weak Assertions & Enforced Strict Tri-State Semantics:
   - Removed arbitrary exit code 1 checks and stdout coincidence checks.
   - A step is PASS only when its exact functional property is demonstrated.
   - Roles with unwired cloud infrastructure (worker blob storage, scheduler token)
     are strictly marked `BLOCKED`, never promoted to `PASS`.

D. Fixed Evidence-Marker Generation:
   - Fixed step naming mismatch: "Non-Root User Execution" emits `NON_ROOT_USER_PASS`.
   - Markers derive directly from structured result objects (`r.marker`), eliminating
     string-matching coincidence.

E. PostgreSQL-Backed Live Proof:

   - Executes real Alembic migrations (`migrate` role) to head -> `MIGRATION_EXECUTION_PASS`.
