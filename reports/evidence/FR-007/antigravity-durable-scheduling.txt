1. EXECUTIVE SUMMARY & RESOLUTION OF W11 REQUIREMENTS
--------------------------------------------------------------------------------
Wave 11 permanently resolves Acceptance Criteria A-7, A-8, and removes synchronous
bulk feed maintenance from founder-facing request paths:

A. A-8: Durable Source Scheduling & Cadence State
   - Implemented `source_schedules` table via Alembic migration `0007_source_schedules.py`:
       Columns:
         source_id VARCHAR(128) PRIMARY KEY
         cadence_hours FLOAT NOT NULL
         last_attempt_at TIMESTAMP NULL
         last_success_at TIMESTAMP NULL
         next_due_at TIMESTAMP NOT NULL (INDEXED)
         cooldown_until TIMESTAMP NULL (INDEXED)
         consecutive_failures INTEGER NOT NULL DEFAULT 0
         last_status VARCHAR(32) NULL
         error_message TEXT NULL
         created_at TIMESTAMP NOT NULL
         updated_at TIMESTAMP NOT NULL
   - Persisted source schedules survive scheduler and worker process restarts:
     * Restart is NOT bootstrap: existing rows are queried directly and preserved.
     * Bootstrap rule: never-polled sources have next_due_at set to now (immediately eligible);
       sources with existing run history compute next_due_at = last_attempt + cadence_hours.
     * Prevents all-source warm-up storms upon container restart or deployment rollouts.
   - Integrated into scripts/backup_restore.py, scripts/check_cloud_readiness.py,
     and tests (14 passed in check_cloud_readiness, 4 passed / 3 skipped in backup_restore).

B. A-7: Asynchronous, Due-Only Poll Now HTTP Semantics
   - Updated `POST /api/worker/poll-now`:
     * Accepts optional payload `{"source_id": str | None, "force": bool = False}`.
     * In generic mode (`source_id=None`), evaluates all read-allowed sources and enqueues
       ONLY those whose durable next_due_at <= now, skipping sources that are not_due,
       cooling_down, already_queued, or read_disabled_by_policy.
     * In explicit mode (`source_id="remoteok"`), checks policy permissions, cooldown,
       and active queue status; enqueues when due or when `force=True`.
     * Returns HTTP 200 asynchronously immediately after enqueuing jobs to `worker_jobs`.
       Never performs network ingestion or match evaluation inline during the HTTP request.
     * Leaves current feed visible and intact (`GET /api/opportunities` verified).

C. Async Projection Maintenance on Founder Settings Writes
   - Replaced synchronous `_refresh_current_pack_projections` calls in:
       `PUT /api/filters/{filter_id}`
       `PUT /api/facets/{facet_id}`
       `POST /api/hidden-reasons/unhide`
     with `_enqueue_pack_projection_refresh(session, request)` which enqueues an
     idempotent `refresh_feed_projections` job to `worker_jobs`.
   - Settings writes return immediately without traversing feed projections or opportunities.
   - Registered `make_refresh_feed_projections_handler` in `default_handler_registry()`,
     allowing background worker runners to refresh projections asynchronously.
   - Repeated rapid writes execute idempotently without corrupting projection state.
