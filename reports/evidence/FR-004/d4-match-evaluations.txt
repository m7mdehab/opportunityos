--- Reload fidelity, measured rather than assumed ---

D4b reported that a persisted OpportunityRecord cannot reconstruct an
Opportunity faithfully: adapters store responsibilities/requirements
provenance as an item COUNT ('3 items'), not the text, and re-deriving them
from the stored description would not reproduce fetch-time results either,
because description = clean_text(raw_desc) while the adapters extract from
the UNCLEANED raw_desc. Leaving them empty rather than re-deriving is
therefore correct: re-derivation would yield two different scores for the
same posting depending on which path produced it.
